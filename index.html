Homelab

A documented, sanitized self-hosted setup: Proxmox VE + ZFS, Docker deployed via Coolify, per-host Traefik reverse proxies, Cloudflare Tunnels, a k3s Kubernetes cluster, and Home Assistant OS.

All hostnames, IPs and secrets are replaced with placeholders for public sharing. Source of truth: README and docs/architecture.md.

Key design decisions

  • Coolify as the deploy layer — every container is a Coolify service/application; compose files carry coolify.* labels and an external per-service network.
  • Per-host Traefik (v3.6) — each VM runs its own proxy on 80/443/8080 with the Docker provider; Let's Encrypt HTTP-challenge for public certs plus a private-CA cert served for internal *.example.home hosts.
  • Zero inbound ports — public access rides Cloudflare Tunnels terminating at Traefik inside the LAN.
  • k3s is separate from Coolify — k3.l workloads are plain kubectl apply manifests; only Traefik comes from k3s' bundled Helm controller (plain-HTTP ingress, no cert-manager).
  • Layered backups — sanoid snapshots + ZFS replication of zpool_home/data to pbs.l, plus nightly vzdump of every VM/CT into the PBS pbs-vms datastore (verify weekly, prune daily, GC weekly).
  • ZFS + sanoid — single pool, recursive 15-minute snapshots, VM dumps to a backup dataset; media/Nextcloud data on NFS-exported datasets, bind-mounted into containers.
  • Secrets never in compose — everything is ${VAR} from .env; the repo ships only .env.example.

Lessons learned

  • Coolify keeps generated compose under /data/coolify/ (root-owned); from a non-root account you reconstruct them from docker inspect (labels + env + mounts).
  • Healthcheck commands can embed real credentials (e.g. Transmission's curl -u user:pass) — always scrub them before sharing.
  • Container names encode Coolify UUIDs — treat them as opaque identifiers.
  • HAOS must be inventoried with the ha CLI, not docker; never commit its config files (they carry tokens, coordinates, device IDs).
  • k3s: never commit kubeconfig, Secret resources, or private images — note their existence in prose, redact status/metadata, and scrub seed-data configmaps that embed real accounts and bcrypt hashes.
  • PBS: verify backup claims from the backup server itself; keep API tokens, authkey.key, proxy.key, and notification configs (a Telegram webhook embeds the live bot token + chat id) out of the repo.

Repository layout

configs/
  pve/                     # ZFS / storage / backup notes + sanoid.conf
  col/                     # Coolify control plane + its Traefik
  apps/                    # Node.js apps + cloudflared (apps.l)
  home/                    # home services + Traefik + internal-CA config (home.l)
  tools/                   # Gitea, Jenkins, n8n, Authentik, Transmission, tunnels (tools.l)
  k3l/                     # k3s cluster manifests + notes (k3.l)
  pbs/                     # Proxmox Backup Server: jobs/schedules + notes (pbs.l)
  haos/                    # Home Assistant OS capabilities (prose only)

Every configs/<host>/<service>/ folder contains a sanitized docker-compose.yml and an .env.example with placeholder keys — copy the example to .env, fill in real values, keep it out of git.
